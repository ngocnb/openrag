# External Integrations

**Analysis Date:** 2026-03-20

## APIs & External Services

**LLM Providers:**
- OpenAI (GPT-4o, GPT-4 Turbo, etc.)
  - SDK: openai (AsyncOpenAI)
  - Auth: `OPENAI_API_KEY` environment variable
  - Validation: `src/services/models_service.py` - Lightweight API key validation without consuming credits
  - Models: Listed in `src/config/model_constants.py` (OPENAI_VALIDATION_MODELS, gpt-4o default)

- Anthropic (Claude models)
  - SDK: anthropic
  - Auth: `ANTHROPIC_API_KEY` environment variable
  - Models: claude-opus-4-5, claude-sonnet-4-5, claude-haiku-4-5, etc. (ANTHROPIC_VALIDATION_MODELS)
  - Default: claude-sonnet-4-5-20250929

- IBM WatsonX
  - Auth: `WATSONX_API_KEY`, `WATSONX_ENDPOINT`, `WATSONX_PROJECT_ID`
  - Embedding models: IBM Granite and Slate models + third-party models
  - Dimensions: Configuration in `src/config/settings.py` (WATSONX_EMBEDDING_DIMENSIONS)

- Ollama (Local inference)
  - Connection: `OLLAMA_ENDPOINT` environment variable
  - Protocol: HTTP API at specified endpoint
  - Validation: Lightweight health check via `/api/tags` endpoint
  - Default model pattern: gpt-oss

**Cloud Storage & Object Storage:**
- AWS S3
  - SDK: boto3 1.35.0+
  - Auth: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`
  - Optional: `AWS_S3_ENDPOINT` (for S3-compatible services), `AWS_REGION`
  - Implementation: `src/connectors/aws_s3/` - Connector for S3 bucket ingestion
  - API Endpoints: List buckets, bucket status checks, file metadata

- IBM Cloud Object Storage
  - SDK: ibm-cos-sdk 2.13.0+
  - Auth modes:
    - IAM: `IBM_COS_API_KEY` + `IBM_COS_SERVICE_INSTANCE_ID`
    - HMAC: `IBM_COS_HMAC_ACCESS_KEY_ID` + `IBM_COS_HMAC_SECRET_ACCESS_KEY` + `IBM_COS_AUTH_ENDPOINT`
  - Connection: `IBM_COS_ENDPOINT`
  - Implementation: `src/connectors/ibm_cos/` - Connector for COS bucket ingestion
  - Features: Composite file IDs (bucket::key format), prefix filtering, lifecycle management

## Data Storage

**Vector Database:**
- OpenSearch 3.0.0+ (Primary)
  - Connection: `OPENSEARCH_HOST` (default: opensearch), `OPENSEARCH_PORT` (default: 9200)
  - Auth: `OPENSEARCH_USERNAME`, `OPENSEARCH_PASSWORD`
  - Client: opensearch-py 3.0.0[async] with AIOHttpConnection
  - Configuration: `src/config/settings.py` and `src/utils/opensearch_utils.py`
  - Indices:
    - `documents` (default, configurable via `OPENSEARCH_INDEX_NAME`) - Vector search and document storage
    - `api_keys` - API key storage with encryption
  - Vector dimensions: 1536 (default), 3072 (for text-embedding-3-large)
  - KNN settings: EF_CONSTRUCTION=100, M=16, disk_ann method

**File Storage:**
- Local filesystem: `./openrag-documents` (configurable via `OPENRAG_DOCUMENTS_PATH`)
- S3/IBM COS: Optional cloud storage connectors
- Encrypted credential files: Stored locally in `./config/` directory (AES-256-GCM encryption)

**Caching:**
- In-memory session caching via Python dictionaries
- Redis: Not currently integrated

## Authentication & Identity

**OAuth2 Providers:**
- Google OAuth2
  - Endpoints: accounts.google.com, oauth2.googleapis.com
  - Client: `GOOGLE_OAUTH_CLIENT_ID`, `GOOGLE_OAUTH_CLIENT_SECRET`
  - Scopes: openid, email, profile, drive.readonly, drive.metadata.readonly
  - Implementation: `src/connectors/google_drive/oauth.py` (GoogleDriveOAuth class)
  - Token storage: Encrypted credentials file (handled via encryption utility)

- Microsoft Graph (Azure AD)
  - SDK: msal 1.29.0+
  - Client: `MICROSOFT_GRAPH_OAUTH_CLIENT_ID`, `MICROSOFT_GRAPH_OAUTH_CLIENT_SECRET`
  - Use cases: SharePoint, OneDrive integration
  - Implementation: `src/connectors/sharepoint/oauth.py`, `src/connectors/onedrive/oauth.py`

**Internal Auth:**
- Langflow API Key: `LANGFLOW_KEY` (auto-generated if not provided)
  - Generation: Uses Langflow superuser credentials (`LANGFLOW_SUPERUSER`, `LANGFLOW_SUPERUSER_PASSWORD`)
  - Retry logic: `LANGFLOW_KEY_RETRIES` (default: 15), `LANGFLOW_KEY_RETRY_DELAY` (default: 2.0s)
- Session Secret: `SESSION_SECRET` (auto-generated if not provided, for session management)
- JWT Tokens: Generated by `src/session_manager.py` with custom claims (aud: ["opensearch", "openrag"])

**Encryption:**
- Master key: `OPENRAG_ENCRYPTION_KEY` (Base64 AES-256-GCM)
- Implementation: `src/utils/encryption.py`
- Tenant binding: `OPENRAG_TENANT_ID` for verifying encrypted file ownership
- Password hashing: Bcrypt for OpenSearch admin (stored as hash)

## Monitoring & Observability

**Error Tracking:**
- Langfuse (Optional)
  - Keys: `LANGFUSE_SECRET_KEY`, `LANGFUSE_PUBLIC_KEY`
  - Host: `LANGFUSE_HOST` (defaults to Langfuse Cloud if unset)
  - Integration: Configured in Langflow environment (`docker-compose.yml`)
  - Used for tracing workflow executions

**Health Monitoring:**
- Provider health checks: `src/api/provider_health.py`
  - OpenAI: Lightweight models endpoint validation
  - Anthropic: Models endpoint validation
  - Ollama: `/api/tags` endpoint check
  - WatsonX: API endpoint validation
- Docling service health: `src/api/docling.py` - `/health` endpoint

**Logs:**
- Structured logging via structlog (JSON format by default)
- Log level: `LOG_LEVEL` (DEBUG, INFO, WARNING, ERROR, CRITICAL) - default: INFO
- HTTP access logging: Enabled by default, disable with `ACCESS_LOG=false`
- Service name: `SERVICE_NAME` (default: openrag)
- No color output: `NO_COLOR` flag for CI/CD environments

## CI/CD & Deployment

**Hosting:**
- Docker/Docker Compose (primary)
- Multi-container architecture: Frontend (Next.js), Backend (FastAPI), Langflow, OpenSearch, Dashboards
- Image registry: Assumes ECR or Docker Hub (langflowai/openrag-*)

**Environment File:**
- `.env.example` - Template with all configuration options
- No `.env` file committed (security)
- Auto-generation of secrets if not provided (encryption keys, API keys)

**Deployment Configuration:**
- Port mapping:
  - Frontend: `FRONTEND_PORT` (default: 3000)
  - Backend: 8000 (exposed in `Dockerfile.backend`)
  - Langflow: `LANGFLOW_PORT` (default: 7860)
  - OpenSearch: 9200 (JSON API), 9600 (node-to-node)
  - OpenSearch Dashboards: 5601
- Data persistence: Volumes for `opensearch-data`, `openrag-documents`, `keys`, `flows`, `config`, `data`
- Version pinning: `OPENRAG_VERSION` environment variable (default: latest)

## Webhooks & Callbacks

**Incoming:**
- Webhook base URL: `WEBHOOK_BASE_URL` (optional, enables continuous ingestion)
  - Must be publicly routable from external services
  - Example: ngrok tunnel for local development
  - Used for webhook triggers from cloud storage connectors

**Outgoing:**
- No direct outgoing webhooks; integration via pull-based connectors:
  - Google Drive, SharePoint, OneDrive, AWS S3, IBM COS
  - Continuous ingestion requires polling mechanism (facilitated by Langflow)

**Task Management:**
- Long-running operations: Document ingestion tracked via task IDs
- Timeout configurations:
  - `LANGFLOW_TIMEOUT` (default: 2400s / 40 min) - HTTP call timeout
  - `LANGFLOW_CONNECT_TIMEOUT` (default: 30s) - Connection timeout
  - `INGESTION_TIMEOUT` (default: 3600s / 60 min) - Per-file processing timeout
  - `UPLOAD_BATCH_SIZE` (default: 25) - Files per batch upload

## Langflow Integration

**Purpose:** Document ingestion, chat workflows, vector search pipelines

**Configuration:**
- Base URL: `LANGFLOW_URL` (default: http://localhost:7860)
- Public URL: `LANGFLOW_PUBLIC_URL` (for UI links, default: auto-detected)
- Flow IDs:
  - `LANGFLOW_CHAT_FLOW_ID` (1098eea1-...) - Chat execution flow
  - `LANGFLOW_INGEST_FLOW_ID` (5488df7c-...) - Document ingestion flow
  - `LANGFLOW_URL_INGEST_FLOW_ID` (72c3d17c-...) - URL crawling ingestion
  - `NUDGES_FLOW_ID` (ebc01d31-...) - Nudge/suggestion generation flow

**Headers & Global Variables:**
- Headers: `X-Langflow-Global-Var-SELECTED_EMBEDDING_MODEL`, `X-Langflow-Global-Var-OPENSEARCH_URL`, etc.
- Management: `src/utils/langflow_headers.py`, `src/utils/langflow_utils.py`
- Service: `src/connectors/langflow_connector_service.py`, `src/services/langflow_file_service.py`

**Authentication:**
- Auto-login (optional): `LANGFLOW_AUTO_LOGIN` (default: False)
- Superuser: `LANGFLOW_SUPERUSER`, `LANGFLOW_SUPERUSER_PASSWORD` (for key generation)
- New user active by default: `LANGFLOW_NEW_USER_IS_ACTIVE` (default: False)

## Docling Integration

**Purpose:** Advanced document processing (PDF, images, structured documents)

**Service URL:** `DOCLING_SERVE_URL` (default: http://host.docker.internal:5001)
- Overridable for remote instances
- Used in document ingestion pipeline for OCR and layout analysis

**Configuration:**
- OCR Engine: `DOCLING_OCR_ENGINE` (optional, e.g., tesseract)
- Worker processes: `DOCLING_WORKERS` (default: 1)
